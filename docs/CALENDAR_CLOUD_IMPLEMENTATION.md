# Calendar & Cloud Implementation Notes

## What was set up

Two new standalone desktop apps were added to Local Butler:

- **Local Butler Calendar** (`local-butler-calendar`)
- **Local Butler Cloud** (`local-butler-cloud`)

They are separate apps with their own `.desktop` entries, not tabs inside the Diagnostic app.

---

## 1. Local Butler Calendar (Radicale)

### What Radicale does
Radicale is a tiny CalDAV/CardDAV server. It keeps calendars and contacts as ordinary `.ics` and `.vcf` files in your home directory. With it running on `127.0.0.1:5232`, any CalDAV client on the same machine (GNOME Calendar, Evolution, Thunderbird, etc.) can read/write your calendar without any external cloud.

### Files created/changed
| File | Purpose |
|------|---------|
| `~/.config/radicale/config` | Radicale server config (localhost only, htpasswd auth) |
| `~/.config/radicale/users` | bcrypt htpasswd file with `local:local` |
| `~/.local/share/radicale/collections` | Calendar/contact storage root |
| `~/.config/systemd/user/radicale.service` | User systemd service |
| `~/local-butler/src/local_butler/apps/calendar/main.py` | GTK app source |
| `~/.local/bin/local-butler-calendar` | Launcher script |
| `~/.local/share/applications/local-butler-calendar.desktop` | App grid shortcut |

### Security choices
- Listens only on `127.0.0.1:5232` (not `0.0.0.0`), so nothing outside the machine can reach it.
- Uses htpasswd auth with `plain` encryption on localhost only. Username `local`, password `local`.
  - The server is bound to loopback, so the password is only used by local CalDAV clients; network attackers cannot reach the port.
  - If you want a stronger hash later, install `bcrypt`/`python3-bcrypt` and regenerate `~/.config/radicale/users` with `htpasswd` using `bcrypt`.
- Runs as your normal user, not root.

### How to connect a calendar client
Use this CalDAV account:
- **URL:** `http://127.0.0.1:5232/local/calendar/`
- **User:** `local`
- **Password:** `local`

If GNOME Calendar is not installed, the app shows a hint to run `sudo dnf install gnome-calendar evolution-data-server`.

### What the app does
- Start / stop the Radicale service.
- Create a default calendar collection on first start.
- Show the CalDAV URL, user, and detected calendar client.
- Open GNOME Calendar/Evolution/Thunderbird if installed.

## 2. Local Butler Cloud (Syncthing)

### What Syncthing-as-a-service entails
Syncthing is a peer-to-peer continuous file synchronizer. Instead of syncing to a company’s server, it syncs directly between devices you own. Running it as a **systemd user service** means:
- It starts automatically when you log in.
- It runs under your user account.
- It has its own isolated config/home directory.
- You control it from a web UI or from the Local Butler Cloud app.

### Files created/changed
| File | Purpose |
|------|---------|
| `~/.config/syncthing-local-butler/` | Dedicated Syncthing home/config directory |
| `~/.config/syncthing-local-butler/config.xml` | Syncthing config (generated by Syncthing itself) |
| `~/Sync/` | Default shared folder (created by Syncthing) |
| `~/.config/systemd/user/local-butler-syncthing.service` | User systemd service |
| `~/local-butler/src/local_butler/apps/cloud/main.py` | GTK app source |
| `~/.local/bin/local-butler-cloud` | Launcher script |
| `~/.local/share/applications/local-butler-cloud.desktop` | App grid shortcut |

### Why a separate config home
The system already had a `syncthing.service` with `ExecStart=%h/bin/syncthing serve ...` but no explicit home directory. I created `local-butler-syncthing.service` with `--home=%h/.config/syncthing-local-butler` so:
- It does not collide with any other Syncthing instance.
- It can be cleanly enabled/disabled from Local Butler.
- The service name clearly belongs to Local Butler.

### What the app does
- Start / stop the Syncthing service.
- Show the device ID, configured folders, and paired devices.
- Open the Syncthing Web UI (`http://127.0.0.1:8384`).
- Open the default `~/Sync` folder.
- Polls every few seconds to refresh status.

### Adding another device
1. Open Syncthing Web UI from the app.
2. On the other device, install Syncthing and copy its device ID.
3. Add the device ID on both sides and choose which folders to share.
4. Files sync directly over LAN or over the internet via encrypted relay if you enable it.

## 3. Differences from Google/OneDrive

| Feature | Google/OneDrive | Local Butler setup |
|---------|-----------------|--------------------|
| Server | Company datacenter | Your own machine |
| Sync | Client ↔ cloud | Peer-to-peer (Syncthing) |
| Calendar | Google/Outlook cloud | Radicale on localhost |
| Data access | Provider can read files | Only you hold the keys |
| Internet required | Yes | No for LAN sync |

---

## 4. How to manage the services from the terminal

```bash
# Calendar
systemctl --user status radicale.service
systemctl --user start radicale.service
systemctl --user stop radicale.service
systemctl --user enable radicale.service   # autostart on login

# Cloud
systemctl --user status local-butler-syncthing.service
systemctl --user start local-butler-syncthing.service
systemctl --user stop local-butler-syncthing.service
systemctl --user enable local-butler-syncthing.service
```

---

## 5. Known limitations / next steps

- No GUI calendar client is installed yet. The Calendar app will prompt you to install GNOME Calendar.
- The default Radicale password is `local` for convenience. Change it in production.
- Syncthing must be paired manually with other devices; the Local Butler app does not yet automate pairing.
- If you already had a Syncthing service running, the new `local-butler-syncthing.service` is independent and uses a fresh config home. The Cloud app warns you if the old `syncthing.service` is still active.
